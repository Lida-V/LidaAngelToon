# 対応範囲と確認方法

## 対応

- Blender 5.2.1 LTS / EEVEE。Windows上の原始図形で、ノード生成、適用、元の出力への復帰、再適用、保存再読込、描画を確認済みです。
- Blender付属の `bpy` / `mathutils` を使用。通常の導入にはpipは不要です。
- 手続き画像の再生成だけPython 3.10以上、NumPy、Pillowが必要です。依存物は同梱しません。
- Unity、Unreal Engine、Cycles、モバイル・VR性能、別のBlender版は未実装または未検証です。
- パネルの登録・適用操作は背景実行で確認しています。プリファレンス画面やパネルの手動クリック、他OSの画面操作は未検証です。

## よくあるつまずき

| 症状 | 確認すること |
|---|---|
| シェーダーが見えない | EEVEEか、ビューが「レンダー」表示か、アクティブ材質に適用したか |
| 適用が拒否される | Principled BSDFと元のMaterial Outputがある単純な材質で試す |
| 影が想定と違う | 初期値では落ち影を受けない。オンにする場合はSun1個・環境光0で試す |
| 白が明るすぎる | ノードのHighlight Kneeを下げる。シーンの露出やBloomも別に確認する |
| 髪の筋が横向き | 毛筋画像を読むUVのV方向を髪の長さ方向へ合わせる |
| 輪郭線が太い・割れる | mmで調整。開いた面や分離した法線では線が割れやすいため、輪郭線を外して比較する |
| 別の物体も変わった | 共有材質が原因。Copy shared materialをオンにして、制作ファイルのコピーで試す |

## 実装上の区切り

光の方向・色はSunから読む共通グループです。1つのblend内では1個の主光を共有するため、複数シーンで別々のSunを同時に使う構成には対応していません。明るい側の色はEmissionとして出すため、Sunのenergyを下げることは露出を下げる操作と同じではありません。Receive ShadowはEEVEEのShader to RGBによる白拡散面の校正値を使うため、複数ライトや明るいワールドで一般的なPBRの影を再現するものではありません。

AOは利用者が用意した属性を読みます。ポーズで変わるAOの計算、顔の頬や顎の検出、髪の根元・毛先の検出、モデルのウェイト修正、VRMへの変換はしません。

## リリース検査

`manifest.json` は配布対象の明示的な一覧です。検査スクリプトは未列挙ファイル、モデル拡張子、シンボリックリンク、PNG署名、ローカル絶対パスや典型的な秘密鍵表記を確認します。すべての機密や権利を自動で判定する検査ではありません。

Blender確認用コマンドは [README](../README.md) を参照してください。生成した原始図形のblend/PNG/JSONは `dist/` に置き、公開ZIPには含めません。
